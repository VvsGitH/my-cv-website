# The type is chosen, self-hosted, and cut at build time

> Merges and replaces ADR-0012, ADR-0020, ADR-0022 and ADR-0023, which are gone. This is the only ADR about fonts.

The CV sets itself in its own faces, not the reference PDF's: **JetBrains Mono** for display — the name, the subtitle, section headings, entry titles, contact labels — **Atkinson Hyperlegible** for everything read as prose, **Primera Signature** on the signature, **icomoon** on the Toolbar. Garet, Now and Lato are gone.

Every face is self-hosted. `src/assets/fonts/<family>/` holds the raw sources, committed — the only copy of anything in this pipeline. The `.woff2` a visitor downloads is cut from them on every `astro build` and every `astro dev` start, into `.astro/subset-fonts/`, which is git-ignored. **Nothing derived is committed.**

The pipeline is three files and no more:

- **`fonts.config.mjs`** — one declaration per family (`cssVariable`, `display`, `fallbacks`, `charset`, `variants`), where each face is named exactly once, plus two adapters: `toAstroFonts()` for Astro's `fonts`, `toSubsetTasks()` for the integration.
- **`scripts/subset-fonts.mjs`** — an Astro integration that imports nothing from the project. It takes `{ source, target, charset }` tasks and cuts them in `astro:config:setup`.
- **`astro.config.mjs`** — the entrypoint, calling both adapters.

The faces reach the page through `<Font>` in the two heads this site has, `BaseLayout.astro` and `pages/[locale]/og.astro`. No stylesheet writes an `@font-face`; `src/styles/fonts.css` maps the emitted variables onto role tokens and remains the record of which face plays which role.

## Considered Options

- **A CDN.** Rejected: a network dependency in the PDF capture is a determinism hazard (ADR-0009).
- **Buying a Garet licence** and keeping the reference's type. Rejected: the one commercial face in the stack, on a public repo served from GitHub Pages — exactly the case a webfont EULA is written about. Choosing type outright costs nothing and settles it.
- **`fonttools` / `pyftsubset`.** Rejected for the `subset-font` npm package (harfbuzz/wasm), which keeps the toolchain to Node with no Python dependency.
- **Subsetting to the literal glyphs the content uses.** Rejected for a charset — Basic Latin + Latin-1 + Latin Extended-A + the typographic punctuation the copy uses. Glyph-exact subsets would mean re-cutting after every content edit; the charset has already paid off, the Italian translation needed no re-cut.
- **A real signature image.** Rejected on the owner's behalf: the signature is a script-face approximation precisely **so the owner's actual signature is never published on a public site**. Do not "improve" it into a scan.
- **Committing the subsets beside their sources.** Rejected: two coupled assets versioned per face is a copy that can silently disagree with what it was copied from, and the build only ever read the derivative.
- **A custom `FontProvider` that subsets inside `resolveFont`.** Verified to work — byte-identical output — then rejected: a provider runs inside unifont, which Astro creates with `throwOnError: false`, so an unreadable source **succeeds** the build with two warnings and ships the page in Courier New. In `astro:config:setup` the same failure is exit code 1. A provider also runs once per Vite environment, where the hook runs once.
- **`updateConfig({ fonts })` from the integration**, rewriting the paths after cutting. Rejected: `updateConfig` **concatenates arrays** (`core/config/merge.js:33`), so a config that declares `fonts` and an integration that updates it produce eight families, two per `cssVariable`. Naming the generated paths up front keeps the config declarative.
- **A cache that skips the work.** Rejected: it would have to key on the source bytes *and* the charset *and* the subsetter version, and getting that wrong ships a stale font from a green build. Not having one cannot. The whole set costs ~1.0s.
- **`fallbacks: ['cursive']` for the signature**, which is the honest generic. Rejected: Astro's `DEFAULT_FALLBACKS` covers serif, sans-serif, monospace and the `ui-*` family and nothing else, so `cursive` produces no metric-matched fallback at all. `['sans-serif']` keeps one. The chain is less honest and the rendering is unchanged.
- **A variable JetBrains Mono.** Not pursued: three static instances subset to 34–35 kB each, and the CV uses three points on the axis.
- **Keeping `fontaine`.** Gone. As a Vite plugin at `enforce: 'pre'` it ran before Vite inlined the CSS `@import`s, saw only import lines, found no `@font-face`, and generated nothing for years — while the tokens named `'X fallback'` faces that did not exist. A PostCSS wrapper repaired it, but only positionally. Astro does the same job inside its own pipeline, with no such seam.

## What was measured

- **The reductions, logged on every build**: JetBrains Mono −63%, Atkinson −27/28%, Primera Signature −40%, icomoon −98% (81.6 kB down to 1.7 kB, the single biggest win in the pipeline).
- **`size-adjust`**: **99.9837%** for JetBrains Mono against Courier New, **99.3717%** for Atkinson against Arial. A single `['Arial']` behind everything gave the monospace face **134.59%**, which is why the generic matters.
- **Drift between each real face and its fallback**, measured on the built page over real content: 0.00% on the name, 0.03% a section heading, 0.00% the longest paragraph, 1.74% a short employer line, 5.15% a two-word bullet, 8.50% a bold term. `size-adjust` is one factor calibrated on average character width — exact over a paragraph, approximate over two words.
- **Preloads: 7 links, 155 kB of the 161 kB shipped** — everything but the signature, all drawn above the first fold. That is close to "fetch the whole set eagerly"; the alternative is a `preload={[{ weight: 800 }]}` filter, worth revisiting if the LCP ever needs the bandwidth back. The OG route preloads nothing: a headless capture waits on `document.fonts` and gains nothing from a hint.
- **The guard fires** on a subset put where a source belongs — `came out no smaller than it went in (16780 -> 16780 bytes)`, exit code 1. A missing source is exit code 1 with the path in the message.
- **`astro preview` and `astro check` do no subsetting.** `astro:config:setup` is not a build hook — it is where an integration is handed the config, so Astro calls it for every command, and `scripts/render-captures.mjs` starts a preview once per capture.
- **A warm run writes nothing**: eight `unchanged` lines, identical mtimes. In `astro dev`, touching a source re-runs the hook (`addWatchFile`) and costs exactly **one** restart, because nothing was written — had the files been rewritten, Astro's own font watcher would have fired a second.
- **The suite is green, 90/90.** Both PDFs match on page geometry, extracted text and font resources; both OG cards are byte-identical PNGs. The PDFs themselves are not byte-comparable — two captures of the same commit differ — so that comparison is structural, run through the suite's own reader.

## Consequences

- **Nothing derived may ever be written into `src/assets/fonts/`.** Subsetting is idempotent, so a subset sitting where a source belongs round-trips and reports success. It happened once, to `AtkinsonHyperlegible-Bold.woff2`: the build was green, the PDF was right, and only the byte counts caught it. With no committed copy left, every glyph outside the charset would be gone from the only file in the repo — so the output tree lives outside `src/`, mirrors the source tree, and always ends in `.woff2` because Astro reads a face's type off its extension (two of the eight sources are `.ttf`).
- **The family name in the CSS carries a hash.** `resolve-family.js` sets `uniqueName` to `${name}-${hashObject(family)}`, so the page declares `font-family:"JetBrains Mono-4d7510d73ecc041e"`, and it moves whenever anything in that family's config changes. **Nothing may be written that depends on the name being stable** — no literal `font-family: 'JetBrains Mono'`, no assertion on the string. `tests/pdf.spec.ts` reads PostScript names out of the embedded font programs instead, which this does not touch.
- **A new head means a new set of `<Font>` calls.** The variables exist only where the component renders, and the failure is quiet: an undefined variable makes the whole `font-family` declaration invalid, so text falls back to whatever it inherits and the icons draw their private-use codepoints as tofu.
- **The face CSS is an inline `<style>` in every head, and it is unlayered** — outside `global.css`'s `@import ... layer(base)` chain. Variable resolution does not care about layers, so the tokens read it normally, but it is the one exception to the layer discipline in this repo.
- **`optional` is forbidden.** It is a determinism hazard for the capture, which stays gated on `document.fonts.ready` (ADR-0009). `swap` on the text faces, `block` on the icons — the fallback for a private-use codepoint is tofu, and briefly-nothing beats briefly-tofu. `fallbacks` must end in a generic or Astro generates no metric-matched fallback at all.
- **Astro's per-weight fallback is unreachable, and bold prose is no better for it.** For Atkinson it generates `Arial` at 99.3717% for the 400 cuts and `Arial Bold` at 92.2954% for the 700, in that order. CSS matches family before weight, so bold text takes the plain `Arial` and synthesises the weight: 8.50% drift as the chain stands, 6.61% if `Arial Bold` were reached. Nothing in the config reorders this without putting a bold fallback behind regular text, which is worse.
- **The shipped bytes are not reviewable, and `subset-font` is pinned for it.** `"subset-font": "2.7.0"`, no caret — the same treatment `@biomejs/biome` gets. A subsetter upgrade that changes the output used to show up as a diff on eight tracked files and now shows up nowhere, which is why the byte counts and ratios stay in the build log: they are the only remaining window onto the derivative.
- **CI runs the subsetter.** `subset-font` stays a devDependency — correct for a static build — but it is a build dependency in practice, and a broken source is a red CI run rather than a bad font from a green one.
- **No face reaches the PDF as Type3.** Garet and Now were CFF, which Chromium redrew as anonymous glyph procedures; JetBrains Mono and Atkinson are TrueType, so every face is named and embedded and the suite asserts the set by name in both directions (ADR-0009, ADR-0010). Re-add a CFF face and that blind spot returns with it.
- **Licensing.** Both text families are SIL OFL with their licence files beside them — `src/assets/fonts/atkinson/OFL.txt`, `.../jetbrains/OFL.txt` — and the repo distributes only the original faces, never a derivative. **Primera Signature has no licence on record**, and its full `.ttf` is committed to a public repo. Known and accepted, not overlooked.
- **The folder is an archive, not a manifest.** All 16 JetBrains Mono cuts and all four Atkinson cuts are committed, so a future weight is a line in `fonts.config.mjs` rather than a re-download; `variants` is what decides what ships. Atkinson's BoldItalic is unshipped: italic is the Languages proficiency labels and nothing else, and that `dd` renders `entry.level` as a bare expression, so bold inside italic is unreachable rather than merely unused.
- **JetBrains Mono ExtraBold is declared at 800, its real weight**, and `--font-weight-name` / `--font-weight-heading` name 800 to match. An earlier pass declared it 900 and left `font-weight: 800` falling back to Bold — which is why weights and styles are spelled out in `fonts.config.mjs` rather than inferred off the file, though the provider would read them.
- **`scripts/subset-font.d.ts` exists** because `subset-font@2.7.0` ships no types and the pipeline is `// @ts-check`ed. It declares the one call this repo makes.
- **`FontFamily` is not exported from `astro`, so `fonts.config.mjs` recovers it** as `NonNullable<AstroUserConfig<never, never, [LocalProvider]>['fonts']>[number]`, and derives the developer-facing family type from it — so `cssVariable`, `display` and the rest stay checked against Astro's own schema. `variants` and `src` are non-empty tuples there, which `.map()` widens to plain arrays: hence the `[first, ...rest]` shape in the adapter, which also makes an empty `variants` a config-time error.
- **Adding a face**: drop the source in `src/assets/fonts/<family>/`, add a variant in `fonts.config.mjs` — one place, and the charset comes from its family — and, for a new family, map its `cssVariable` to a role token in `src/styles/fonts.css`. Nothing to run, nothing generated to commit.
