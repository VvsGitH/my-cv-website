# The faces are declared to Astro, and fontaine is gone

Every face the CV draws with is declared in `fonts.config.mjs`, handed to `astro.config.mjs` as its `fonts`, and reaches the page through `<Font>` in the two heads this site has — `BaseLayout.astro` and `pages/[locale]/og.astro`. No stylesheet in `src/styles/` writes an `@font-face` any more. `src/styles/fonts.css` keeps the role tokens and nothing else, each one a single `var()` onto the variable Astro emits; `src/styles/icons.css` keeps its glyph rules and its `!important` and gives up its face declaration like the rest.

`fontaine`, `scripts/fontaine-after-imports.mjs` and the `vite.css.postcss` block that carried it are deleted. Astro generates the metric-matched fallbacks now, in its own pipeline, and emits the `rel="preload"` links the page never had.

> **Superseded on the subsetting axis by ADR-0023.** The faces are still declared exactly as below, but `src` now names a file the build generates: the subsets are cut at build time into `.astro/`, `src/assets/raw-fonts/` is gone, and no generated `.woff2` is committed. The five-step recipe at the end is three.

**The subsetting pipeline is untouched, for now.** Astro ships no subsetter — `fonts/providers/local.js` normalizes the paths it is given and reads metrics off the file, nothing more — so `scripts/subset-fonts.mjs`, `src/assets/raw-fonts/`, the committed `.woff2` in `src/assets/fonts/` and ADR-0020's rule that CI never runs the subsetter all stand. This ADR supersedes ADR-0020 on the fallback-generation axis only.

## Considered Options

- **Keeping fontaine.** Rejected. ADR-0020 records what it cost: as a Vite plugin at `enforce: 'pre'` it ran before Vite inlined the CSS `@import`s, saw five import lines, found no `@font-face`, and generated nothing for the whole life of ADR-0012 — while `fonts.css` named `'X fallback'` faces that did not exist. The PostCSS wrapper repaired that, but positionally: PostCSS is the one stage where the imports are inlined *and* the `url()`s are still as authored, so any change to how Vite handles CSS puts it back in the failure mode, silently. Astro doing the same job inside its own pipeline has no such seam.
- **Leaving `icons.css` to declare its own face.** Rejected on the owner's call, and the earlier draft of this work argued the other way — that running an icon face through a system built for text fallbacks gains nothing and costs a second mechanism. What settles it is that the cost turned out to be zero: `display: 'block'` is a first-class config value, `fallbacks: []` yields a variable holding one family and no generic, and the `!important` never moves. One mechanism, and the file keeps everything that made it worth reading.
- **Moving the subsetting into the build**, via a custom `FontProvider` that runs `subset-font` inside `resolveFont`. Verified to work — the emitted file came out byte-identical to the committed subset — and deliberately deferred. It belongs to its own decision, and it has a trap worth naming here: a provider runs inside unifont, which Astro creates with `throwOnError: false`, so an unreadable source **succeeds** the build with two warnings and a page whose text renders in Courier New. The built-in `local()` provider fails loudly on the same input, because its read happens outside that swallow. If the subsetting ever does move into the build, it goes in an integration hook, not a provider.
- **`fallbacks: ['cursive']` for the signature**, which is the honest generic and the one it used to end on. Rejected: Astro's `DEFAULT_FALLBACKS` covers serif, sans-serif, monospace and the `ui-*` family and nothing else, so `cursive` produces no metric-matched fallback at all — `optimizeFallbacks` bails and the face is left bare. `['sans-serif']` keeps the Arial-derived fallback fontaine used to give it. The chain is less honest and the rendering is unchanged.

## What was measured

The size-adjust numbers Astro computes are ADR-0020's numbers: **99.9837%** for JetBrains Mono against Courier New, **99.3717%** for Atkinson against Arial, where ADR-0020 recorded 99.98% and 99.37% from fontaine. Same metrics source, same output.

Drift between the real face and its fallback, measured on the built page with a `Range` over real content, the real face dropped from the front of the chain:

| | drift |
| --- | --- |
| the name, JetBrains Mono 800 | 0.00% |
| a section heading, JetBrains Mono 800 | 0.03% |
| the longest paragraph, Atkinson 400 | 0.00% |
| a short employer line, Atkinson 400 | 1.74% |
| a two-word bullet, Atkinson 400 | 5.15% |
| a bold term, Atkinson 700 | 8.50% |

The short-string numbers are not a regression, they are what `size-adjust` is: one factor calibrated on average character width, so it is exact over a paragraph and approximate over two words. The bold row is the one worth knowing about — see the consequences.

Both PDFs came out with identical page geometry, identical extracted text and identical font resources against the pre-migration build, and both OG cards are **byte-identical** PNGs. The suite is green, 90/90, `icomoon-feather` still embedded by name in both PDFs. (The PDFs themselves are not byte-comparable: two captures of the same commit differ, so the comparison is structural.)

## Consequences

- **Astro's per-weight fallback is unreachable, and bold prose is no better than it was.** For Atkinson it generates two faces — `Arial` at `size-adjust: 99.3717%` for the 400 cuts, `Arial Bold` at 92.2954% for the 700 — and puts both in the variable, in that order. CSS matches family before weight: the plain `Arial` fallback contains the glyph, so bold text never reaches `Arial Bold` and gets synthetic bolding instead. Measured: 8.50% drift through the chain as it stands, 6.61% if `Arial Bold` were reached. Nothing in the config can reorder this without putting a bold fallback behind regular text, which is worse. It matches what fontaine gave us — one fallback per family, weight-agnostic — so this changes nothing; it just is not the improvement it looks like.
- **The family name in the CSS carries a hash.** `resolve-family.js` sets `uniqueName` to `${name}-${hashObject(family)}`, so the page declares `font-family:"JetBrains Mono-4d7510d73ecc041e"` and `document.fonts` reports the fallback as `"Atkinson Hyperlegible-… fallback: Arial"`. The hash moves whenever anything in that family's config changes, so **nothing may be written that depends on the name being stable** — no literal `font-family: 'JetBrains Mono'`, no assertion on the string. `tests/pdf.spec.ts` is unaffected: it reads PostScript names out of the embedded font programs, which this does not touch.
- **A new head means a new set of `<Font>` calls.** The variables exist only where the component renders. `pages/[locale]/og.astro` writes its own head and had to be wired separately, icon face included — the card draws Sheet 1 and the only icon inside a Sheet sits on Sheet 2 today, but which Sheet a Block sits on is content, not layout (ADR-0002). Forget this and the failure is quiet: an undefined variable makes the whole `font-family` declaration invalid, so text falls back to whatever it inherits and the icons draw their private-use codepoints as tofu.
- **The face CSS is an inline `<style>` in every page's head, and it is unlayered.** It sits outside `global.css`'s `@import ... layer(base)` chain. Variable resolution does not care about layers, so the tokens read it normally, but it is the one exception to the layer discipline in this repo and it is here rather than in a comment nobody reads.
- **A `biome-ignore` had to go.** Behind a `var()` biome cannot see a font name, so `useGenericFontNames` stops firing on `icons.css` and its suppression became an unused-suppression warning. The reasoning it carried — *a fallback would render the missing-glyph box instead of the icon* — is now where the decision lives: the `fallbacks: []` in `fonts.config.mjs`, pointing at ADR-0020. `noImportantStyles` still fires and its suppression stays.
- **A missing font file fails the build.** `local()` reads the file to hash and to copy it, outside unifont's error swallow, so a wrong path in the config is an `UnknownFilesystemError` and a red build — not a page that silently ships in fallbacks.
- **`optional` is still forbidden**, `swap` on the text faces and `block` on the icons, exactly as ADR-0020 left it. The capture stays gated on `document.fonts` (ADR-0009).
- **Everything but the signature is preloaded** — all three JetBrains Mono cuts, all three Atkinson cuts and icomoon, because all of them are drawn above the first fold. That is **7 links and 155 kB of the 161 kB shipped**, so the preloads are close to "fetch the whole set eagerly"; the alternative is a filter (`preload={[{ weight: 800 }]}` and friends) that names the two or three faces the first paint cannot do without and lets the rest arrive with the CSS. Worth revisiting if the LCP ever needs the bandwidth back. The OG route preloads nothing: a headless screenshot waits on `document.fonts` and gains nothing from a hint.
- **`FontFamily` is not exported from `astro`, so the config file recovers it.** Splitting the families into `fonts.config.mjs` costs the contextual typing `defineConfig` gave them inline: a bare `const` widens `display: 'swap'` to `string` and the array stops being assignable. Annotating with `AstroUserConfig['fonts']` does not fix it either — unparameterized, that branch types `options` as `undefined`. What works is reading the element type back out of the mapped tuple: `NonNullable<AstroUserConfig<never, never, [LocalProvider]>['fonts']>[number]`. Verified live under `tsc`: `display: 'blocky'` is a TS2820, not a silent `any`.
- **Adding a face is now five steps**, four of them unchanged: drop the source in `src/assets/raw-fonts/<family>/`, add it to `variants` in `scripts/subset-fonts.mjs`, run `npm run fonts:subset`, **add the family or variant to `fonts.config.mjs`**, and map it to a role token in `src/styles/fonts.css` — then commit the generated `.woff2` alongside the raw.
