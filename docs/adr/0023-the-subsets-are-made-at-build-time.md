# The subsets are made at build time, and only the sources are versioned

`src/assets/fonts/` holds the raw faces — one file per face, the only copy of anything in this pipeline. The `.woff2` a visitor downloads is cut from them on every `astro build` and every `astro dev` start by `scripts/subset-fonts.mjs`, running as an Astro integration in `astro:config:setup`, and written to `.astro/integrations/subset-fonts/`, which is git-ignored. `src/assets/raw-fonts/` is gone, and so are the eight generated `.woff2` that used to be committed beside it.

`fonts.config.mjs` gained `FONT_SUBSETS` — the source-to-charset table, the charsets themselves and the icon codepoints, all of which used to live in the subsetter. Each variant's `src` now names a generated file through `subsetOf()` (`scripts/font-paths.mjs`), so the config declares what the build makes rather than what the repo stores. `npm run fonts:subset` still works, writing where the build writes; it is an inspector now, not a step in anyone's workflow.

This reverses ADR-0012 on **hand-subsetting over build-time subsetting**, and ADR-0020 on **versioning the derivatives**. Everything else in both stands: self-hosting over a CDN, a charset rather than glyph-exact subsets, `subset-font` over `pyftsubset`, the signature as a script face, and every raw cut kept as an archive.

## Considered Options

- **Leaving it as it was.** Rejected on the second seam, not the first: the manual step was survivable, but two coupled assets versioned for every face is a copy that can silently disagree with what it was copied from, and nothing in the repo enforced that it did not. The build only ever read the derivative.
- **A custom `FontProvider` that subsets inside `resolveFont`.** Rejected, and measured before being rejected (ADR-0022): a provider runs inside unifont, which Astro creates with `throwOnError: false`, so an unreadable source **succeeds** the build with two warnings and ships the page in Courier New. In `astro:config:setup` the same failure is exit code 1. A provider also runs twice per build, once per Vite environment, where the hook runs once.
- **`updateConfig({ fonts })` from the integration**, rewriting the paths after cutting. Rejected: `updateConfig` **concatenates arrays** (`core/config/merge.js:33`), so a config that declares `fonts` and an integration that updates it produce eight families, two per `cssVariable`, and every face is emitted twice. Naming the generated paths up front in `fonts.config.mjs` sidesteps it and keeps the config declarative.
- **The source and its charset as keys on the family or the variant**, which would have made the manifest one list instead of a table plus eight `subsetOf()` calls. Not possible, and this is worth recording because it looks like it should be: Astro's `FontFamilySchema` is a zod strict object and rejects an unknown key on a family (`! Unrecognized key: "charset"`), and `Variant` is an interface, so an extra key on a variant is a TypeScript error (`TS2353`). `options` is a loose record at runtime; the types are not, and this repo type-checks its config.
- **A cache that skips the work.** Rejected on the owner's call, and it is the right call: a cache would have to key on the source bytes *and* the charset *and* the subsetter version, and getting that wrong ships a stale font from a green build. Not having one cannot. The whole set costs ~1.0s.
- **Generating the families from a single table**, so a source is named exactly once. Not pursued at eight faces: it buys one mention and costs a config that is computed rather than read. A mismatch between the table and a `subsetOf()` call is a red build, not a silent one.

## What was measured

- **The eight faces are byte-identical to what the previous commit shipped.** Same subsetter, same charsets, same bytes: `b1ffb69b…` for JetBrainsMono-Regular, `0d24c37c…` Bold, `04943bf8…` ExtraBold, `f23d3324…` / `e53e962c…` / `2e367a5b…` for Atkinson Regular / Bold / Italic, `e1fb3dcc…` for PrimeraSignature, `3d77474c…` for icomoon-feather. Because Astro's asset id is a content hash, **even the URLs are unchanged** — `dist/_astro/fonts/75f56021cf8e8fcd.woff2` is the same file name as before, so no visitor's cache is invalidated by this.
- **The reductions, logged on every build**: JetBrains Mono −63%, Atkinson −27/28%, Primera Signature −40%, icomoon −98%.
- **`npm test` is green (90), the two OG cards are byte-identical PNGs**, and both PDFs match the pre-migration build on page geometry, extracted text and font resources. The PDFs are not byte-comparable — two captures of the same commit differ — so that comparison is structural, run through the suite's own reader.
- **The guard fires on the failure ADR-0020 could only diagnose after the fact.** Putting a subset where a source belongs: `jetbrains/JetBrainsMono-Regular.woff2 came out no smaller than it went in (34380 -> 34380 bytes)`, and the build stops. ADR-0020's symptom, now an error.
- **A missing source is exit code 1** with the path in the message.
- **`astro preview` and `astro check` do no subsetting**, verified on their logs. Both would otherwise: `astro:config:setup` is not a build hook, it is where an integration is handed the config, so Astro calls it for every command — including `preview`, which `scripts/render-captures.mjs` starts once per capture.
- **A warm run writes nothing.** Eight `unchanged` lines and identical mtimes. In `astro dev`, touching a source re-runs the hook (`addWatchFile`) and costs exactly **one** restart, because nothing was written: had the files been rewritten, Astro's own font watcher would have fired a second one — measured separately, a `touch` on a resolved font file logs `[assets] Font file updated` and restarts Vite.

## Consequences

- **The shipped bytes are no longer reviewable, and `subset-font` is pinned because of it.** A subsetter upgrade that changes the output used to show up as a diff on eight tracked files; now it shows up nowhere. `"subset-font": "2.7.0"`, no caret — the same treatment `@biomejs/biome` gets, for the same reason. The byte counts and ratios in the build log are the only remaining window onto the derivative, which is why they are still printed.
- **CI runs the subsetter now**, which is the half of ADR-0012 this ADR reverses outright. `subset-font` stays a devDependency — correct for a static build, and `npm i` in CI installs it — but it is a build dependency in practice, and a broken source is now a red CI run rather than a bad font from a green one.
- **The generated directory must keep agreeing with the integration's name.** `createCodegenDir()` derives `.astro/integrations/<name>/` from it, and `scripts/font-paths.mjs` names that path statically so `fonts.config.mjs` can point through it. The hook asserts the two match and throws if Astro's naming ever moves, rather than leaving a comment about it.
- **Nothing derived may ever be written into `src/assets/fonts/`.** Subsetting is idempotent, so a subset sitting where a source belongs round-trips and reports success — and with no committed copy left, every glyph outside the charset would be gone from the only file in the repo. The output tree lives outside `src/` for that reason, mirrors the source tree so the two read side by side, and always ends in `.woff2` because Astro reads a face's type off its extension (two of the eight sources are `.ttf`).
- **Adding a face is three steps now**, down from five: drop the source in `src/assets/fonts/<family>/`, add it to `FONT_SUBSETS` and to the family's `variants` in `fonts.config.mjs`, and map it to a role token in `src/styles/fonts.css`. Nothing to run, nothing generated to commit.
- **The repo carries 2.0 MB of sources and no derivatives**, where it used to carry 2.0 MB plus 180 kB. The saving is not the point; `git status` staying clean after a build, and there being one file per face to be right about, is.
- **`scripts/subset-font.d.ts` exists** because `subset-font@2.7.0` ships no types and `subset-fonts.mjs` is `// @ts-check`ed like the config files it works with. It declares the one call this repo makes.
- **The licence files moved with their faces** — `src/assets/fonts/atkinson/OFL.txt` and `.../jetbrains/OFL.txt`. After this the repo distributes only the original faces, never a derivative of them. Primera Signature's missing licence is unchanged and still known (ADR-0020).
