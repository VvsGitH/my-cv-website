# Self-hosted, hand-subset fonts, from a git-ignored raw-drop folder

> **Superseded on the raw-folder and face-selection axes by ADR-0020.** The raw sources are no longer git-ignored: they live in **`src/assets/raw-fonts/`, committed**, precisely because the split below left a clean clone unable to regenerate anything. The faces changed with them — Garet, Now and Lato are gone, and `FACES` is now a `TEXT_FONTS` / `ICON_FONTS` pair. **Superseded on hand-subsetting-over-build-time-subsetting by ADR-0023**, which moved the cutting into the build and stopped committing its output. **What survives here is the rest of the reasoning**: self-hosting over a CDN, `subset-font` over `pyftsubset`, a charset rather than glyph-exact subsets, and the signature as a script face rather than a scan. Read ADR-0023 for the shape of the pipeline today; read this for why it is shaped that way at all.

Every face the CV uses is self-hosted and subset by hand. The owner drops raw source files into **`docs/assets/`, which is git-ignored**; `scripts/subset-fonts.mjs` (`npm run fonts:subset`) reads from there and writes `.woff2` into **`src/assets/`, which is committed**. The script is manual and out-of-band: **CI never touches `docs/assets/` and never runs the subsetter.**

Get that split wrong — add a face to `FACES` and commit without running the script, or make the build depend on the raw folder — and CI fails on a path that does not exist in a clean clone.

## Considered Options

- **Google Fonts or another CDN.** Rejected: a network dependency in the PDF capture is a determinism hazard (ADR-0009), and three of the four families are licensed files the owner supplies rather than anything a CDN serves.
- **Subsetting at build time.** Rejected: it would put the raw sources in the repo or in CI, and the subsetting tool in the production dependency tree, to save a step that runs when a font changes — roughly never. **Taken by ADR-0023**, once both premises had gone: ADR-0020 put the raws in the repo for reasons of its own, and the tool never was a production dependency — this is a static site, so `subset-font` sits in `devDependencies` and runs before the bytes are baked. What tipped it was not the manual step but the second copy: versioning a derivative beside its source is a pair that can silently disagree.
- **`fonttools` / `pyftsubset`.** Rejected in favour of the `subset-font` npm package (harfbuzz/wasm), which keeps the toolchain to Node with **no Python dependency**.
- **Subsetting to the literal glyphs the content uses.** Rejected: the charset is Basic Latin + Latin-1 + Latin Extended-A + common typographic punctuation — enough for any Italian or English CV copy. Glyph-exact subsets would mean **re-subsetting after every content edit**, and this has already paid off: the Italian translation needed no re-subset.
- **A real signature image.** Rejected on the owner's behalf: the signature is a script-font approximation precisely **so the owner's actual signature is never published on a public site**. Do not "improve" it into a scan.

## Consequences

- Only the faces actually used are shipped. Subsetting cut each file 75–80% against the `.otf`/`.ttf` sources of the day; ADR-0020 records what it cuts against today's already-optimised woff2 sources, which is less.
- **Never `optional`.** It is a determinism hazard for PDF capture; capture is gated on `document.fonts.ready` instead (with the viewport caveat in ADR-0009). This ADR also mandated `font-display: block`, and **that half is superseded**: the text faces are `swap` (ADR-0020), `icons.css` stays `block`.
- ~~The `fontaine` Vite plugin generates metric-matched `local()` fallbacks for every `@font-face` in `fonts.css` indiscriminately, so a new face gets one for free and needs no per-font config.~~ **This was never true.** Fontaine's Vite plugin runs before Vite inlines CSS `@import`s, so it never saw `fonts.css` at all and generated nothing for the life of this ADR — the `'X fallback'` names in the tokens pointed at faces that did not exist. ADR-0020 records the fix (fontaine as a PostCSS plugin) and the per-family configuration it needed. What was right: those fallbacks resolve against whatever the machine has, so one going missing is expected rather than a failure.
- `--font-weight-signature` exists despite the face having one weight, so the signature is not the single role that inlines its weight.
- `.signature` is set at 1.6rem rather than the reference-derived 1.05rem: the system-cursive placeholder and the real script face do not share metrics, and 1.6rem is what matches the reference at the real face's proportions.
- The role-to-face mapping was read out of the reference PDF's own font resources (ADR-0014), not inferred by rendering comparison — an earlier pass did the latter and got Now and Garet swapped. That mapping no longer governs anything: the CV picks its own faces (ADR-0020). **`src/styles/fonts.css` remains the accurate record of which face plays which role.**
- ~~Adding a face is three steps: drop the source into `docs/assets/fonts/`, add it to `FACES`, run `npm run fonts:subset`, then commit the generated `.woff2`.~~ Superseded — see ADR-0020, where all the steps are inside the repo. The point behind it stands: **skipping the subset-and-commit breaks CI in the sense that nothing local reproduces it.**
